## Результати експериментів

### 1. Експеримент із XSS-атакою (Урок №1)

Я додала товар із назвою `<script>alert(1)</script>`, але скрипт не запустився в браузері.

* **Перегляд коду сторінки (Ctrl+U):** `<script>` було замінено на `&lt;script&gt;alert(1)&lt;/script&gt;`.
* **Висновок:** Django автоматично екранує HTML-код у змінних, тому JavaScript не виконується. Це допомагає захиститися від XSS-атак.

### 2. Експеримент із DEBUG = False (Урок №4)

Я змінила `DEBUG = True` на `DEBUG = False` у файлі `settings.py`. Після цього таблиця та меню перестали відображатися зі стилями CSS.

* **Пояснення:** коли `DEBUG=True`, Django сам роздає статичні файли під час розробки. При `DEBUG=False` це вже не працює, тому в продакшені для цього потрібно використовувати веб-сервер, наприклад Nginx або WhiteNoise.

### 3. Експеримент із CSRF-захистом (Урок №5)

Я видалила приховане поле `csrfmiddlewaretoken` через DevTools і спробувала відправити форму. У результаті отримала помилку:

`403 Forbidden: CSRF verification failed. Request aborted.`

#### Чому цей запит було відхилено?

CSRF — це захист від ситуацій, коли сторонній сайт намагається виконати дію від імені користувача.

Django перевіряє спеціальний CSRF-токен під час відправлення форми. Після того як я видалила поле `csrfmiddlewaretoken`, необхідний токен не був переданий, тому Django відхилив запит і повернув помилку 403.
